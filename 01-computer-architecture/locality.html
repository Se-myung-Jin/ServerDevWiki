핵심 요약

참조 지역성은 프로그램이 방금 쓴 데이터를 곧 다시 쓰고, 쓴 데이터의 이웃을 곧 이어서 쓰는 경향이다. CPU와 메모리의 속도 차이를 메우는 캐시는 이 경향이 있다는 가정 위에서만 효과를 낸다.

지역성은 하드웨어가 보장해 주는 성질이 아니다. 데이터를 어떻게 배치하고 어떤 순서로 접근하느냐에 따라 같은 알고리즘, 같은 빅오라도 실행 시간이 몇 배씩 벌어진다.

종류뜻하드웨어가 이용하는 방식흔한 예
시간 지역성같은 주소를 짧은 시간 안에 다시 접근한다최근에 쓴 라인을 캐시에 남겨 둔다(교체 정책)루프 카운터, 누적 변수, 반복 호출되는 함수 코드
공간 지역성접근한 주소의 근처를 곧 접근한다캐시 라인 단위로 한꺼번에 가져온다배열 원소, 같은 구조체의 필드
순차 지역성주소가 일정한 방향과 간격으로 이어진다하드웨어 프리페처가 다음 라인을 미리 가져온다배열을 앞에서부터 순회, 명령어 순차 실행

순차 지역성은 공간 지역성의 특수한 경우로 묶어 두 가지로만 분류하기도 한다.

동작 원리

캐시는 바이트가 아니라 라인 단위로 가져온다

CPU가 메모리에서 4바이트 정수 하나를 읽으면, 캐시는 그 값이 들어 있는 캐시 라인 전체를 가져온다. x86에서 라인 크기는 보통 64바이트라서 int 16개가 한 번에 올라온다. 그래서 배열을 순서대로 읽으면 첫 원소에서만 메모리까지 가고, 나머지 15개는 캐시에서 바로 읽힌다.

L1 캐시 히트는 몇 사이클이면 끝나지만, 메인 메모리까지 가면 수백 사이클이 걸린다. 그래서 미스 횟수가 성능을 거의 결정하고, 미스 횟수는 접근 패턴이 결정한다.

지역성은 코드가 만든다

C#의 2차원 배열 int[,]는 행 우선(row-major)으로 저장된다. 한 행의 원소가 메모리에 연달아 놓이고, 그다음 행이 이어진다. 같은 배열을 행 방향으로 돌면 메모리를 순서대로 읽지만, 열 방향으로 돌면 접근할 때마다 행 길이만큼 건너뛴다. 

var grid = new int[Rows, Cols];
long sum = 0;

// 행 우선 순회: 메모리에 놓인 순서대로 읽는다
for (int r = 0; r < Rows; r++)
    for (int c = 0; c < Cols; c++)
        sum += grid[r, c];

// 열 우선 순회: 읽을 때마다 Cols * 4바이트씩 건너뛴다
for (int c = 0; c < Cols; c++)
    for (int r = 0; r < Rows; r++)
        sum += grid[r, c];

두 루프는 같은 원소를 같은 횟수만큼 읽는다. 차이는 루프 순서 하나뿐인데, 배열이 캐시보다 크면 열 우선 쪽이 눈에 띄게 느려진다.

명령어에도 지역성이 있다

CPU는 실행할 명령어도 메모리에서 읽어 명령어 캐시(L1i)에 올린다. 명령어는 대부분 순서대로 실행되고(순차 지역성) 루프는 같은 코드를 반복한다(시간 지역성). 그래서 명령어 캐시는 보통 데이터 캐시보다 적중률이 높다. 반대로 가상 호출이나 분기가 많아 실행 경로가 여러 곳으로 흩어지면 명령어 캐시 미스가 늘어난다.

선택 기준

어떤 지역성을 노릴지는 데이터를 어떻게 쓰는지 보고 정한다. 같은 데이터를 또 쓰면 시간 지역성, 이웃 데이터를 이어서 쓰면 공간 지역성, 한 방향으로 쭉 훑으면 순차 지역성을 노린다.

접근 패턴노릴 지역성방법
작은 데이터에 여러 번 연산한다
예: 시야 범위 안 객체끼리 충돌 검사		 시간 다 쓰기 전에 캐시에서 밀려나지 않도록 작업 단위를 캐시 크기에 맞게 쪼갠다(타일링). 같은 데이터를 쓰는 연산은 루프 하나로 합친다.
많은 원소를 한 번씩 훑는다
예: 매 틱 모든 몬스터 위치 갱신		 공간 + 순차 원소를 연속 배열에 둔다. 그 루프에서 쓰는 필드만 따로 모은다(SoA, 핫/콜드 분리). 앞에서 뒤로 순서대로 돈다.
키로 드문드문 조회한다
예: 세션 ID로 플레이어 찾기		 기대하기 어렵다 조회 한 번에 건드리는 캐시 라인 수를 줄인다. 포인터를 여러 번 따라가는 구조보다 배열 기반 해시나 노드가 넓은 트리(B-트리 계열)가 유리하다.

게임 서버에서는

게임 서버의 틱 루프는 "많은 원소를 한 번씩 훑는" 패턴의 전형이다. 여기서 C#의 class와 struct 차이가 그대로 지역성 차이가 된다. 

// class 배열: 배열에는 참조(8바이트)만 연속으로 놓이고,
// 실제 객체는 힙 여기저기에 있을 수 있다. 원소마다 포인터를 한 번 더 따라간다.
class Monster
{
    public Vector3 Position;
    public Vector3 Velocity;
    public string Name;
    public List<Item> DropTable;
    // ... 이동 처리와 상관없는 필드들
}
Monster[] monsters;

// struct 배열: 값 자체가 배열 안에 연속으로 놓인다.
// 이동 틱에서 쓰는 필드만 모아 두면 캐시 라인 하나에 더 많은 원소가 들어간다.
struct Motion
{
    public Vector3 Position;
    public Vector3 Velocity;
}
Motion[] motions;

for (int i = 0; i < motions.Length; i++)
    motions[i].Position += motions[i].Velocity * dt;
  • 핫/콜드 분리: 매 틱 쓰는 필드(위치, 속도, 상태)와 가끔 쓰는 필드(이름, 드롭 테이블, 로그용 정보)를 다른 배열이나 객체로 나눈다. 핫 데이터만 훑을 때 캐시에 쓸데없는 바이트가 올라오지 않는다.
  • Dictionary 순회: Dictionary<long, Player>를 foreach로 돌면 내부 엔트리 배열은 순서대로 읽는다. 하지만 값이 class면 결국 원소마다 흩어진 객체를 따라가야 한다. 매 틱 전체를 훑어야 한다면 키 조회용 사전과 별도로 순회용 연속 배열을 두는 것을 고려한다.
  • 패킷 버퍼: 수신 버퍼를 앞에서부터 순서대로 파싱하는 것은 순차 지역성이 좋은 패턴이다. 버퍼를 작은 조각으로 쪼개 리스트로 이으면 이 이점이 줄어든다.

주의 사항

  • 작은 벤치마크는 착시를 만든다. 데이터 전체가 L1/L2에 들어가면 어떤 순서로 접근해도 차이가 거의 없다. 실제 서비스에 가까운 크기로 측정해야 한다.
  • 빅오가 같아도 실제 시간은 다르다. 배열과 연결 리스트 순회는 둘 다 O(n)이지만, 연결 리스트는 노드마다 다른 라인일 수 있어 미스가 훨씬 많다.
  • 공간 지역성이 오히려 해가 되는 경우가 있다. 서로 다른 스레드가 쓰는 변수가 같은 캐시 라인에 있으면, 논리적으로는 공유하지 않는데도 라인이 코어 사이를 오가며 느려진다(false sharing). 자세한 내용은 캐시 일관성과 false sharing에서 다룬다.
  • 2의 거듭제곱 간격 접근은 조심한다. 4096바이트처럼 큰 2의 거듭제곱 간격으로 접근하면 같은 캐시 세트로 몰려 충돌 미스가 생길 수 있다. 열 우선 순회에서 행 길이가 딱 2의 거듭제곱일 때 특히 그렇다.
  • GC가 배치를 바꾼다. .NET에서 연달아 할당한 객체는 처음에는 힙에 가깝게 놓이는 경향이 있다. 하지만 오래 살면서 할당과 해제가 섞이면 흩어진다. "지금 빠르다"가 계속 빠르다는 뜻은 아니다.
