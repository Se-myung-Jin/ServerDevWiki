먼저 읽을 것: 프로세스 메모리 구성 · 호출 스택

핵심 요약

값 형식과 참조 형식을 가르는 것은 대입하거나 넘길 때 무엇이 복사되느냐다. 값 형식(struct, int, enum)은 내용 전체가 복사되고, 참조 형식(class, string, 배열, 대리자)은 객체를 가리키는 참조만 복사된다. 그래서 값 형식 두 변수는 서로 독립이고, 참조 형식 두 변수는 같은 객체를 함께 본다.

"값 형식은 스택, 참조 형식은 힙"은 결과를 거칠게 요약한 말이지 정의가 아니다. 값은 그것을 담은 저장 공간이 사는 곳에 놓인다. 클래스의 필드나 배열 원소인 값 형식은 그 객체와 함께 힙에 있고, 클로저가 잡은 지역 변수와 await를 넘어 사는 지역 변수도 힙으로 옮겨진다.

동작 원리

객체 헤더없다. 필드만큼의 크기다힙 객체마다 헤더와 타입 정보 포인터(64비트에서 16바이트)가 붙는다

값 형식 안에 참조 형식 필드가 있으면 복사되는 것은 그 참조뿐이다. struct Squad { List<Player> Members; }를 복사하면 두 사본이 같은 리스트를 가리킨다. 사본에서 Members.Add를 하면 원본에도 보인다. "struct라서 독립적"이라는 생각이 깨지는 흔한 자리다.

값이 어디에 놓이나

값 형식이 들어 있는 자리놓이는 곳이유
메서드의 지역 변수, 매개변수스택(또는 레지스터)메서드가 끝나면 함께 사라져도 된다
클래스의 필드그 객체와 함께 힙객체가 사는 동안 남아야 한다
배열의 원소배열과 함께 힙배열이 객체다. 원소가 연속으로 박혀 있다
박싱된 값힙참조로 가리킬 실체가 필요하다(박싱)

await를 넘어 사는 지역 변수상태 기계의 필드. 실제로 멈추면 힙멈춘 동안 스택 프레임이 없어진다(async와 await의 실체)

반대 방향도 있다. 참조 형식의 참조 자체는 지역 변수면 스택에 있다. 그리고 최근 .NET(9 이후)의 JIT는 메서드 밖으로 빠져나가지 않는 객체를 힙 대신 스택에 둔다(탈출 분석). .NET 9는 박스부터 시작했고, .NET 10은 작은 값 형식 배열과 대리자까지 넓혔다. 규격은 어디에 두라고 정하지 않았고, 정하는 것은 수명이다. 그래서 위치보다 "복사되느냐"로 생각하는 쪽이 틀리지 않는다.

매개변수로 넘기는 네 가지 방법

표기넘어가는 것메서드 안에서 할 수 있는 일
(없음)값 형식은 내용의 사본, 참조 형식은 참조의 사본참조 형식이면 객체 내용은 고칠 수 있다. 매개변수에 새 객체를 넣어도 호출한 쪽 변수는 그대로다
ref호출한 쪽 변수 자체의 참조읽고 쓴다. 새 값을 넣으면 호출한 쪽 변수가 바뀐다
out호출한 쪽 변수의 참조반드시 값을 넣고 돌아가야 한다. TryGetValue의 결과 전달
in (C# 7.2), ref readonly (C# 12)읽기 전용 참조읽기만 한다. 큰 struct를 복사 없이 넘길 때 쓴다. 함정은 struct와 class 고르기에서 다룬다

"참조 형식은 참조로 전달된다"는 말은 틀렸다. C#은 기본으로 모두 값으로 전달하고, 참조 형식에서는 그 값이 참조일 뿐이다. 메서드 안에서 player = new Player()를 해도 호출한 쪽은 옛 객체를 그대로 들고 있다. 호출한 쪽 변수를 바꾸려면 ref가 필요하다.

선택 기준

값 형식이 비싸지는 때와 싸지는 때

상황값 형식참조 형식
작은 값을 많이 만든다할당이 없다. GC가 볼 것이 없다객체마다 할당과 헤더, 나중에 GC 비용
배열에 대량으로 담는다원소가 연속으로 박혀 순회가 빠르다(메모리 배치와 자료구조)참조 배열이라 원소마다 다른 곳으로 점프한다
크고 자주 넘긴다넘길 때마다 통째로 복사한다참조 하나만 복사한다
object나 인터페이스로 다룬다박싱으로 할당이 생긴다그대로다

둘 중 어느 것을 정의할지는 struct와 class 고르기에서 기준을 정리한다. 여기서 기억할 것은 하나다. 값 형식은 "할당을 복사로 바꾸는 선택"이다. 작으면 이득이고 크면 손해다.

게임 서버에서는

  • 위치·벡터 같은 작은 값은 struct로 둔다. Vector3, 엔티티 ID, 좌표, 금액은 틱마다 수만 개씩 만들어지고 버려진다. 클래스였다면 그 수만큼 힙 할당과 GC가 생긴다. 반대로 플레이어, 세션, 몬스터처럼 정체성이 있고 여러 곳이 함께 가리키는 것은 class다.
  • 메서드에 struct를 넘겨 고쳤는데 바깥이 안 바뀌는 버그. void ApplyBuff(Stat s) { s.Atk += 10; }는 사본을 고치고 버린다. 고치려면 ref Stat로 받거나 고친 값을 반환한다. 코드 리뷰에서 struct 매개변수를 고치는 줄이 보이면 의심한다.
  • async 메서드의 지역 변수도 할당이 될 수 있다. 패킷 처리기가 await를 넘어 큰 struct를 들고 있으면, 실제로 멈출 때 그 struct가 상태 기계 객체에 담겨 힙으로 간다. 처리기에서 할당을 줄였다고 생각했는데 프로파일러에 상태 기계가 보이는 이유다(Task와 ValueTask).
  • C++의 값 의미와 비슷하지만 같지 않다. C++은 클래스도 값으로 복사되는 것이 기본이라 이동이 필요했고, C#은 class가 참조라 그 문제가 덜하다(이동 시맨틱). C# struct에는 복사 생성자가 없어서 복사는 언제나 바이트 단위다.

주의 사항

  • "값 형식은 스택"은 절반만 맞다. 필드·배열 원소·박스·클로저·async 상태 기계 안의 값 형식은 힙에 있다. 성능 문제가 실제로 생기는 곳이 바로 그 자리들이다.
  • struct 안의 참조 필드는 공유된다. 사본을 만들어도 리스트나 배열 필드는 같은 객체를 가리킨다. 깊은 복사가 필요하면 직접 만든다.
  • 참조 형식도 값으로 전달된다. 매개변수에 새 객체를 넣는 것은 호출한 쪽에 보이지 않는다. 객체의 내용을 고치는 것만 보인다.
  • 값 형식의 기본값은 늘 존재한다. new Point[100]은 생성자 없이 모두 0으로 채워진다. 매개변수 없는 생성자(C# 10부터 선언 가능)도 배열 원소와 default에서는 불리지 않는다.
