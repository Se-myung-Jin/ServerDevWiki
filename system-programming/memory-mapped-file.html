먼저 읽을 것: 가상 메모리 · 페이지 폴트와 스래싱 · 할당과 실제 확보

핵심 요약

메모리 맵 파일은 파일을 주소 공간의 한 구간에 붙여 두고, 그 구간을 배열처럼 읽고 쓰는 방식이다. read를 부르지 않는다. 처음 닿은 페이지에서 페이지 폴트가 나고, 커널이 그 페이지를 파일에서 채워 준다.

read는 커널의 페이지 캐시에서 내 버퍼로 데이터를 복사한다. 매핑은 그 페이지 캐시를 내 주소 공간에 그대로 보이게 한다. 그래서 복사가 없고, 같은 파일을 매핑한 프로세스들은 물리 메모리 한 벌을 함께 쓴다. 대신 폴트 비용을 내고, 입출력 오류가 반환값이 아니라 메모리 접근 예외로 온다.

동작 원리

매핑을 걸고, 닿을 때 채운다

Linux는 mmap에 파일 디스크립터와 길이를 넘겨 주소를 받는다. Windows는 CreateFileMapping으로 매핑 객체를 만들고 MapViewOfFile로 그 일부를 주소 공간에 붙인다. 어느 쪽이든 이 순간에는 파일을 읽지 않는다. 페이지 테이블에 "이 구간은 이 파일의 이 위치"라는 약속만 적는다.

실제로 읽는 것은 그 주소에 처음 닿을 때다. 페이지 테이블에 항목이 없으니 폴트가 나고, 커널은 그 페이지가 이미 페이지 캐시에 있으면 연결만 해 준다(마이너 폴트). 없으면 디스크에서 읽어 온 뒤 연결한다(메이저 폴트). 프로그램이 올라갈 때 실행 파일을 다루는 방식과 같다(프로그램이 올라가는 과정).

페이지 캐시를 직접 본다

그래서 매핑한 파일은 top의 SHR, Windows의 Shared Working Set으로 잡힌다(할당과 실제 확보). 프로세스 열 개가 1GB 파일을 매핑해도 물리 메모리는 1GB 근처만 쓴다. read로 각자 읽어 들이면 사본이 열 벌 생긴다.

공유 매핑과 사적 매핑

방식쓰면Linux / Windows쓰는 곳
공유 매핑페이지 캐시가 바뀐다. 같은 파일을 매핑한 다른 프로세스가 바로 보고, 나중에 파일에도 내려간다MAP_SHARED / PAGE_READWRITE프로세스 사이 데이터 공유, 파일 갱신
사적 매핑처음 쓰는 순간 그 페이지만 내 사본으로 바뀐다(copy-on-write). 파일과 다른 프로세스는 모른다MAP_PRIVATE / PAGE_WRITECOPY실행 파일의 데이터 부분, 읽다가 일부만 고쳐 쓸 데이터
파일 없는 공유 매핑파일 대신 스왑(페이지 파일)이 뒤를 받친다MAP_SHARED | MAP_ANONYMOUS, shm_open / 페이지 파일 기반 CreateFileMapping프로세스 간 공유 메모리(프로세스 간 통신)

공유 매핑에 쓴 내용은 커널이 정한 때에 디스크로 내려간다. 바로 내리려면 Linux는 msync(MS_SYNC), Windows는 FlushViewOfFile 뒤에 파일 핸들로 FlushFileBuffers를 부른다. 쓴 내용은 페이지 캐시에 있으므로 프로세스가 죽어도 남는다. 하지만 OS가 죽거나 전원이 나가면 아직 내려가지 않은 것은 잃는다(파일 시스템).

게임 서버에서는

  • 큰 기획 데이터를 여러 프로세스가 함께 매핑한다. 한 기계에 존 서버 프로세스를 여럿 띄우면, 맵·아이템·몬스터 테이블을 각자 읽어 객체로 풀 때마다 사본이 하나씩 는다. 빌드 때 테이블을 고정 배치의 바이너리 파일로 만들어 두고 읽기 전용으로 매핑하면 한 벌로 끝나고 로딩 시간도 줄어든다. 이때 파일 안에는 포인터 대신 파일 시작에서의 오프셋을 적는다. 매핑되는 주소가 프로세스마다 다르기 때문이다(그 자리에서 읽는 포맷은 게임에서 프로토콜 고르기의 FlatBuffers).
  • .NET에서는 MemoryMappedFile을 쓴다. MemoryMappedFile.CreateFromFile로 열고 CreateViewAccessor의 Read<T>로 구조체를 읽는다. 접근자는 호출마다 범위를 검사해 느리므로, 많이 읽는 경로는 SafeMemoryMappedViewHandle.AcquirePointer로 포인터를 얻어 Span으로 감싸 쓴다(Span과 ref struct). 이름 붙인 매핑(CreateOrOpen, OpenExisting)은 Windows 전용이라 Linux에서는 파일 경로로 공유한다.
  • 데이터를 바꿀 때는 새 파일로 바꿔 끼운다. 매핑 중인 파일 내용을 그 자리에서 덮어쓰면 읽던 프로세스가 반쯤 바뀐 데이터를 본다. 새 파일을 다 쓴 뒤 교체하고, 각 프로세스가 새 파일을 매핑한 다음 옛 매핑을 푼다. Linux는 이름을 바꿔(rename) 옛 파일 자리에 덮어도 되고, 옛 내용은 마지막 매핑이 풀릴 때까지 남는다(파일 시스템). Windows는 매핑 중인 파일을 덮거나 지우지 못하므로 버전마다 다른 이름의 파일을 쓴다.
  • 첫 접근을 틱 밖으로 뺀다. 매핑만 걸고 시작하면 게임 중 처음 닿는 페이지마다 메이저 폴트가 나서 디스크를 기다린다. 로직 스레드에서 그러면 틱이 튄다. 서버 시작 때 한 번 훑거나, Linux MAP_POPULATE·madvise(MADV_WILLNEED), Windows PrefetchVirtualMemory로 미리 올려 둔다.

주의 사항

  • 매핑 중인 파일이 잘리면 Linux 프로세스가 죽는다. 다른 프로세스가 파일을 줄이면 끝 너머가 된 페이지에 닿는 순간 SIGBUS가 오고, 처리하지 않으면 프로세스가 끝난다(시그널과 프로세스 종료). Windows는 매핑된 파일을 줄이지 못하게 막는다.
  • VIRT가 커지는 것은 문제가 아니다. 10GB 파일을 매핑하면 VIRT는 10GB 늘지만 실제로 닿은 페이지만 RES에 잡힌다. 페이지 캐시는 메모리가 모자라면 커널이 거둬 간다.
  • 길이 0인 파일은 매핑할 수 없다. 새 파일에 쓰려면 먼저 파일 크기를 늘린 뒤 매핑한다. 매핑은 파일을 키워 주지 않는다.
  • 공유 매핑으로 프로세스끼리 주고받을 때는 동기화가 따로 필요하다. 같은 메모리를 보는 것은 스레드끼리와 같아서, 원자적 연산이나 프로세스 간 락 없이 쓰면 반쯤 쓴 값을 읽는다(프로세스 간 통신).
