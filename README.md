# ServerDevWiki

> Theory and fundamentals for game server programmers — OS, computer architecture, networking, databases, C#, and deployment/ops.

게임 서버 프로그래머로서 쌓아온(그리고 계속 쌓아가는) 이론적 기반을 한 곳에 정리하는 개인 지식 위키입니다. 실무에서 마주치는 문제를 "어떻게 고쳤는가"가 아니라 "왜 그렇게 동작하는가"까지 거슬러 올라가 정리하는 것을 목표로 합니다.

## 왜 만들었나

실무 코드는 결과만 남고, 그 결과를 뒷받침하는 이론은 머릿속에만 머물다 휘발되기 쉽습니다. 이 레포는 그 이론들을 글로 고정시켜서,

- 나중에 비슷한 문제를 다시 만났을 때 처음부터 다시 고민하지 않도록
- 신입/주니어 동료에게 설명할 때 바로 꺼내 쓸 수 있도록
- 이직/커리어 전환 시 내가 아는 것의 깊이를 스스로, 그리고 남에게 증명할 수 있도록

쌓아가는 기록입니다.

## 구조

```
ServerDevWiki/
├── index.html                 # 홈: 분야 카드와 문서/문항 수
├── quiz.html                  # 점검 문항: 분야·단계를 골라 무작위로 풀기
├── assets/
│   ├── catalog.js             # 분야와 주제 문서 목록 (여기만 고치면 목차가 갱신됨)
│   ├── quiz-data.js           # 점검 문항 (각 문항은 하나의 주제 문서에 연결)
│   ├── app.js · quiz.js       # 사이드바, 목차, 문항 렌더링
│   ├── boot.js                # 테마·본문 폭·학습 모드 복원
│   └── style.css              # 테마(자동/라이트/다크/세피아/터미널)
├── templates/topic.html       # 주제 문서 템플릿
├── 01-computer-architecture/
├── 02-operating-system/
├── ...                        # 분야별 폴더 (각각 index.html + 주제 문서)
├── 16-game-patterns/
└── README.md
```

빌드 단계 없는 정적 HTML이라 `index.html`을 브라우저로 바로 열거나 GitHub Pages로 그대로 호스팅할 수 있습니다.

### 주제 문서 추가하기

1. `templates/topic.html`을 `<분야 폴더>/<slug>.html`로 복사한다.
2. 복사한 파일의 `data-topic`을 `"<분야 폴더>/<slug>"`로 바꾸고 본문을 쓴다.
3. `assets/catalog.js`의 해당 분야 `topics`에 `{ slug, title, level, summary }`를 추가한다.
4. 점검 문항은 `assets/quiz-data.js`에 `{ topic, q, a }`로 추가한다.

본문에서 `<span class="blank">핵심어</span>`로 감싼 부분은 학습 모드에서 가려지고, 클릭하면 드러납니다.

## 작성 원칙

1. **출처가 불분명한 내용은 적지 않는다** — 직접 검증했거나, 신뢰할 수 있는 1차 자료(공식 문서, RFC, 표준 스펙)에 근거한 내용만 남긴다.
2. **"왜"를 먼저, "어떻게"는 그다음** — 메커니즘의 이유를 이해해야 응용이 가능하다.
3. **실무 사례와 반드시 연결한다** — 추상적인 이론으로 끝내지 않고, 실제로 어떤 버그/설계 결정과 이어지는지 남긴다.
4. **계속 고쳐 쓴다** — 한 번 쓰고 끝나는 문서가 아니라, 이해가 깊어질 때마다 갱신한다.
