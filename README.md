# ServerDevWiki

> Theory and fundamentals for game server programmers — OS, computer architecture, networking, databases, C#, and deployment/ops.

게임 서버 프로그래머로서 쌓아온(그리고 계속 쌓아가는) 이론적 기반을 한 곳에 정리하는 개인 지식 위키입니다. 실무에서 마주치는 문제를 "어떻게 고쳤는가"가 아니라 "왜 그렇게 동작하는가"까지 거슬러 올라가 정리하는 것을 목표로 합니다.

## 왜 만들었나

실무 코드는 결과만 남고, 그 결과를 뒷받침하는 이론은 머릿속에만 머물다 휘발되기 쉽습니다. 이 레포는 그 이론들을 글로 고정시켜서,

- 나중에 비슷한 문제를 다시 만났을 때 처음부터 다시 고민하지 않도록
- 신입/주니어 동료에게 설명할 때 바로 꺼내 쓸 수 있도록
- 이직/커리어 전환 시 내가 아는 것의 깊이를 스스로, 그리고 남에게 증명할 수 있도록

쌓아가는 기록입니다.

## 다루는 주제

| 분류 | 내용 |
|---|---|
| **운영체제** | 프로세스/스레드, 스케줄링, 메모리 관리, 동기화, I/O 모델(블로킹/논블로킹, 멀티플렉싱) |
| **컴퓨터 구조론** | CPU 파이프라인, 캐시 계층과 지역성, 메모리 정렬, 분기 예측이 실제 서버 코드 성능에 미치는 영향 |
| **네트워크 프로그래밍** | TCP/IP 스택, 소켓 프로그래밍, IOCP/epoll 같은 비동기 I/O 모델, 패킷 프레이밍·직렬화 설계 |
| **서버 프로그래밍** | 동시성 모델(스레드풀/이벤트루프/액터), 락-프리 자료구조, 게임 서버 특유의 패턴(틱 기반 루프, 세션 관리, Command/Strand) |
| **Database** | 관계형/NoSQL의 트레이드오프, 트랜잭션·격리수준, 인덱싱, 샤딩/레플리케이션, 캐시 전략 |
| **C#** | CLR 내부 동작(GC, JIT), async/await의 실제 메커니즘, Span/Memory를 통한 제로 할당 패턴, 소스 제너레이터 |
| **배포와 운영** | CI/CD, 컨테이너화, 모니터링/로깅, 장애 대응, 수평/수직 확장 전략 |

각 주제는 **기초 → 심화** 순서로 쌓이며, 이론 설명 뒤에는 가능한 한 실제 게임 서버 코드/상황에 빗댄 예시를 붙입니다.

## 구조

```
ServerDevWiki/
├── os/                 # 운영체제
├── computer-architecture/
├── network-programming/
├── server-programming/
├── database/
├── csharp/
├── deployment-ops/
└── README.md
```

각 디렉터리는 독립된 HTML 페이지로 구성되어 있어, 브라우저로 바로 열어보거나 GitHub Pages로 호스팅해 웹에서 바로 열람할 수 있습니다.

## 작성 원칙

1. **출처가 불분명한 내용은 적지 않는다** — 직접 검증했거나, 신뢰할 수 있는 1차 자료(공식 문서, RFC, 표준 스펙)에 근거한 내용만 남긴다.
2. **"왜"를 먼저, "어떻게"는 그다음** — 메커니즘의 이유를 이해해야 응용이 가능하다.
3. **실무 사례와 반드시 연결한다** — 추상적인 이론으로 끝내지 않고, 실제로 어떤 버그/설계 결정과 이어지는지 남긴다.
4. **계속 고쳐 쓴다** — 한 번 쓰고 끝나는 문서가 아니라, 이해가 깊어질 때마다 갱신한다.
