먼저 읽을 것: 해시 테이블

핵심 요약

이진 탐색 트리(BST)는 모든 노드에서 왼쪽 부분 트리는 자기보다 작고 오른쪽은 큰 트리다. 비교할 때마다 절반을 버리므로 높이가 낮으면 O(log n)으로 찾는다.

문제는 높이가 넣는 순서에 달렸다는 것이다. 정렬된 데이터를 차례로 넣으면 한쪽으로만 자라 연결 리스트가 되고 O(n)이다. 그래서 실무에서 쓰는 트리는 넣고 지울 때마다 모양을 다시 잡는 균형 트리이고, 균형을 얼마나 엄격하게 지키느냐가 트리 종류를 나눈다.

동작 원리

같은 값도 넣는 순서에 따라 높이가 달라진다

포화·완전·균형은 서로 다른 조건이다

용어조건쓰임
포화 이진 트리모든 레벨이 꽉 찼다노드 수가 2h − 1로 정해진다
완전 이진 트리마지막 레벨을 뺀 모든 레벨이 꽉 찼고, 마지막 레벨은 왼쪽부터 채워졌다배열에 빈칸 없이 담을 수 있다. 부모·자식 위치가 인덱스 계산으로 나와 포인터가 필요 없다(힙)
균형 이진 트리모든 노드에서 좌우 높이 차가 정해진 범위 안이다높이가 O(log n)으로 유지된다

순회마다 쓰임이 다르다

순회순서쓰임
전위부모 → 왼쪽 → 오른쪽트리 복사, 구조를 그대로 저장·직렬화
중위왼쪽 → 부모 → 오른쪽BST면 정렬된 순서로 나온다
후위왼쪽 → 오른쪽 → 부모자식부터 정리해야 하는 일(삭제, 하위 크기 합산)
레벨위에서 아래로, 같은 레벨은 왼쪽부터가까운 것부터 볼 때. 큐로 구현한다(스택과 큐)

삭제는 자식 수에 따라 세 경우로 나뉜다

지울 노드의 자식어떻게
없다그냥 떼어 낸다
하나그 자식을 지울 노드 자리에 올린다
둘중위 순서의 바로 뒤 값(오른쪽 부분 트리의 최솟값)이나 바로 앞 값(왼쪽의 최댓값)을 가져와 값을 바꾸고, 가져온 쪽 노드를 지운다

자식이 둘인 경우에 가져오는 노드는 반드시 자식이 하나 이하다. 오른쪽 부분 트리의 최솟값은 왼쪽 자식이 있을 수 없기 때문이다. 그래서 세 번째 경우는 앞의 두 경우로 떨어진다.

AVL은 조회가 빠르고, 레드-블랙은 갱신이 싸다

둘 다 균형이 깨지면 회전으로 되돌린다. 회전은 부분 트리의 뿌리를 바꿔 모양만 고치는 연산이라, "왼쪽은 작고 오른쪽은 크다"는 성질은 그대로 남는다.

트리균형 조건회전 횟수맞는 자리
AVL모든 노드에서 좌우 높이 차가 1 이하. 엄격하다삽입은 한 번(단일 또는 이중 회전)으로 끝나지만, 삭제는 뿌리까지 올라가며 여러 번 할 수 있다조회가 압도적으로 많을 때
레드-블랙색 규칙으로 "가장 긴 경로가 가장 짧은 경로의 두 배 이하". 느슨하다삽입·삭제 모두 상수 번(최대 2~3번). 색을 바꾸는 일은 위로 퍼질 수 있다삽입·삭제가 섞여 잦을 때

AVL이 더 납작해서 조회가 조금 빠르고, 레드-블랙은 갱신 때 손대는 범위가 작다. 범용 라이브러리는 대개 갱신 비용이 예측 가능한 레드-블랙을 고른다. C++의 std::map, Java의 TreeMap, .NET의 SortedDictionary·SortedSet이 레드-블랙 트리다.

같은 문제를 이진이 아니라 한 노드에 키를 수백 개씩 담는 다분기로 푼 것이 B-트리다. 균형 이진 트리가 메모리 안에서 비교 횟수를 줄인다면, B-트리는 디스크에서 읽는 블록 수를 줄인다.

트리 노드는 원소마다 따로 할당되어 메모리에 흩어진다. 원소 수가 크지 않고 갱신이 드물면 배열 쪽이 캐시 지역성 덕분에 더 빠를 때가 많다.

게임 서버에서는

  • 순위표는 정렬 구조가 필요한 대표 자리다. "내 앞뒤 10명", "점수 구간별 인원"은 해시로 할 수 없다. 서버 메모리에 두면 SortedSet에 (점수, ID) 쌍을 넣는 식으로 만들고, 서버가 여러 대면 Redis의 정렬 집합(sorted set)을 쓴다. Redis는 균형 트리 대신 스킵 리스트로 같은 연산을 O(log n)에 한다.
  • 시간 순서로 처리할 일은 정렬 트리나 힙에 둔다. 버프 만료, 예약된 이벤트처럼 "가장 이른 것부터"만 필요하면 힙이 더 싸고, 중간 항목을 찾아 취소해야 하면 정렬 트리가 맞다.
  • 재귀로 순회하지 않는다. 균형이 깨진 트리는 깊이가 원소 수만큼 될 수 있고, 재귀 순회는 그 깊이만큼 호출 스택을 쌓는다. 직접 만든 트리를 순회할 때는 명시적 스택으로 반복문을 쓴다.

주의 사항

  • 균형을 잡지 않은 BST는 O(log n)이 아니다. 입력 순서에 따라 O(n)이 된다. 정렬된 데이터를 그대로 넣는 것이 최악이고, ID처럼 증가하는 값이 바로 그 입력이다.
  • 정렬 트리의 키도 넣은 뒤에 바꾸면 안 된다. 넣을 때의 비교 결과로 자리가 정해졌으므로, 점수를 키로 쓴다면 점수가 바뀔 때 빼고 다시 넣는다.
  • 비교 함수는 일관돼야 한다. a < b이고 b < c면 a < c여야 하고, 같은 두 값은 늘 같은 결과를 내야 한다. 점수만 비교해 동점을 "같다"로 처리하면 SortedSet은 동점인 두 번째 원소를 중복으로 보고 넣지 않는다. 동점이면 ID로 한 번 더 비교한다.
