먼저 읽을 것: const와 참조

핵심 요약

클래스 멤버는 클래스에 선언한 순서대로 초기화된다. 생성자의 초기화 목록에 적은 순서는 상관없다. 기반 클래스가 먼저 다 만들어지고 그다음 멤버 차례가 온다. 그래서 뒤에 선언된 멤버로 앞 멤버를 초기화하면 아직 만들어지지 않은 값을 읽는다.

초기화 목록은 멤버를 만드는 자리이고 생성자 본문은 이미 만든 멤버에 대입하는 자리다. 그리고 C++의 지역 변수와 new로 만든 기본 타입은 아무것도 넣지 않으면 정해지지 않은 값을 가진다. 0이 되지 않는다.

동작 원리

멤버 초기화 순서는 선언이 정한다

순서가 선언으로 고정된 데는 이유가 있다. 소멸은 생성의 반대 순서로 해야 하는데, 생성자가 여럿이고 각자 목록 순서가 다르면 소멸 순서를 하나로 정할 수 없다. 그래서 생성자와 상관없이 선언 순서 하나를 기준으로 삼는다. 이런 어긋남은 대개 나중에 멤버를 하나 끼워 넣을 때 생긴다. 경고를 켜 두고 오류로 다룬다.

초기화 목록은 만들고, 본문은 대입한다

구분초기화 목록 : x(v)생성자 본문 { x = v; }
하는 일멤버를 그 값으로 만든다이미 만든 멤버에 대입한다
클래스 타입 멤버생성자 한 번기본 생성자 한 번 + 대입 연산자 한 번
const 멤버, 참조 멤버된다안 된다. 이미 만들어진 뒤라 바꿀 수 없다
기본 생성자가 없는 타입의 멤버된다안 된다. 본문에 들어오기 전에 만들 방법이 없다

목록에 적지 않은 멤버는 본문에 들어가기 전에 기본 초기화된다. 문자열이나 컨테이너 멤버를 본문에서 대입하면 빈 것을 만들었다가 다시 채우는 일을 두 번 한다. 계산이 필요해 본문에서만 정할 수 있는 값이 아니면 목록에서 초기화한다.

값을 안 넣으면 0이 되는 곳과 안 되는 곳

쓰는 법이름int라면클래스라면
int x; (지역), new int기본 초기화정해지지 않은 값. 읽으면 미정의 동작(C++26부터 지역 변수는 "잘못된 동작"으로 바뀐다)기본 생성자 호출
int x; (전역, static)정적 저장 기간은 먼저 0으로 채운다00으로 채운 뒤 생성자 호출
int x{};, new int(), T()값 초기화0사용자 생성자가 없으면 멤버를 0으로 채운 뒤 초기화
int x{5};, int x(5);직접 초기화5맞는 생성자 호출
int x = 5;복사 초기화5explicit이 아닌 생성자만 쓸 수 있다

구조체에 멤버를 나열하고 생성자를 쓰지 않았다면 Packet p;는 모든 필드가 쓰레기값이고, Packet p{};는 모두 0이다. 괄호 한 쌍이 차이를 만든다. C++11부터는 멤버 선언 자리에 기본값을 적을 수 있어서(int hp = 100;) 생성자를 여러 개 두어도 빠뜨리지 않는다.

중괄호 초기화는 잘림을 막고, 초기화 목록 생성자를 먼저 고른다

무엇이 다른가중괄호 T x{...} (C++11)
값이 잘리는 변환컴파일 오류다. int x{3.5};, char c{300};이 막힌다
함수 선언으로 읽히는 문제없다. Widget w();는 함수 선언이지만 Widget w{};는 객체다
std::initializer_list 생성자있으면 그것을 먼저 고른다
 
std::vector<int> a(3, 1);   // 원소 세 개, 모두 1 → {1, 1, 1}
std::vector<int> b{3, 1};   // 원소 두 개, 3과 1 → {3, 1}
std::vector<int> c(10);     // 원소 열 개, 모두 0
std::vector<int> d{10};     // 원소 하나, 10

auto e{1};                   // int. C++17 규칙이지만 결함 수정으로 소급되어 주요 컴파일러는 C++14 모드에서도 int다
auto f = {1};                // 지금도 initializer_list<int>

그래서 원소를 나열할 때만 중괄호를 쓰고, 개수나 크기를 줄 때는 괄호를 쓰는 관행이 자리 잡았다. 그 밖의 자리에서는 잘림을 막아 주는 중괄호가 안전한 기본값이다. C++20에서는 집합체에 멤버 이름을 붙여 초기화할 수 있다(Point p{.x = 1, .y = 2};). 이름은 선언 순서대로만 적을 수 있다.

다른 파일에 있는 전역 객체끼리는 초기화 순서가 정해져 있지 않다

한 번역 단위 안의 전역 객체는 정의한 순서대로 초기화된다. 하지만 서로 다른 .cpp 파일에 있는 전역 객체끼리는 어느 것이 먼저인지 정해져 있지 않다. a.cpp의 로거를 b.cpp의 설정 객체 생성자에서 쓰면, 링크 순서에 따라 아직 만들어지지 않은 로거를 부를 수 있다. 정적 초기화 순서 문제라고 부른다.

흔한 해법은 함수 안의 정적 지역 변수로 감싸는 것이다. 처음 그 선언을 지날 때 초기화되므로 순서가 사용 시점으로 정해진다. C++11부터는 여러 스레드가 동시에 처음 들어와도 초기화가 한 번만 일어나도록 표준이 보장한다. 대신 부를 때마다 초기화가 끝났는지 한 번 확인한다. C++20의 constinit은 전역 변수가 컴파일 시점에 초기화되는지를 검사해, 실행 중 초기화가 끼어들 여지를 없앤다. 

Logger& GetLogger() {
    static Logger instance;   // 처음 부를 때 한 번, 스레드 안전하게 만들어진다
    return instance;
}

선택 기준

  • 멤버는 초기화 목록에서 초기화한다. 본문은 계산이 필요할 때만 쓴다.
  • 목록은 선언 순서대로 적고, 순서 경고(-Wreorder, MSVC C5038)를 오류로 다룬다.
  • 모든 생성자가 같이 쓰는 기본값은 멤버 선언 자리에 적는다.
  • 변수는 선언하면서 바로 값을 넣는다. 값이 없으면 {}로 값 초기화한다.
  • 인자 하나로 부를 수 있는 생성자에는 explicit을 붙인다. 암묵 변환이 필요한 자리에서만 뗀다.

게임 서버에서는

  • 초기화하지 않은 패킷 필드는 메모리 내용을 흘린다. 패킷 구조체를 MovePacket p;로 만들고 일부 필드만 채워 보내면, 나머지 필드와 패딩 바이트에 그 스택 자리에 있던 이전 데이터가 그대로 실려 나간다. 다른 플레이어의 정보나 포인터 값이 클라이언트로 새는 경로다. MovePacket p{};로 만들거나 직렬화할 때 필드를 하나씩 쓴다(정렬과 패딩).
  • 전역 매니저 객체가 서버 시작 때 죽인다. 여러 파일에 흩어진 전역 싱글턴이 서로의 생성자에서 서로를 부르면, 빌드나 링크 순서가 바뀐 날 시작하자마자 크래시가 난다. 전역 객체의 생성자에서는 다른 전역 객체를 건드리지 않고, 서버 시작 함수에서 정해진 순서로 초기화한다.
  • C#은 0으로 채워 주고, C++은 채워 주지 않는다. C#의 필드와 배열 원소는 언제나 0이나 null로 시작하고, 지역 변수는 값을 넣기 전에 읽으면 컴파일 오류다. C++의 지역 변수는 그런 검사가 없어서 경고만 나오거나 아무 말 없이 쓰레기값을 읽는다(구조체 설계).
  • C#과 C++은 기반 클래스와 필드 초기화의 순서가 반대다. C#은 파생 클래스의 필드 초기화식이 기반 클래스 생성자보다 먼저 돈다. C++은 기반 클래스가 먼저 다 만들어진 뒤에 파생 클래스 멤버가 초기화된다. 두 언어를 오가며 기반 생성자에서 파생 쪽 값을 기대하는 코드를 짜면 한쪽에서는 틀린다. 생성자 안에서 가상 함수를 부를 때의 동작도 다르다(가상 함수와 다형성).

주의 사항

  • 초기화 목록의 순서는 초기화 순서를 바꾸지 못한다. 앞 멤버를 뒤 멤버로 초기화하지 않는 것이 유일한 방어다.
  • 초기화하지 않은 값을 읽는 것은 미정의 동작이다. "쓰레기값이 하나 나올 뿐"이 아니라, 컴파일러가 그 읽기를 없는 일로 보고 주변 코드를 바꿀 수 있다(미정의 동작). C++26은 지역 변수의 이 경우를 "잘못된 동작(erroneous behavior)"으로 바꿔, 구현이 정한 값을 읽고 진단할 수 있게 했다. 버그인 것은 같고, 힙 객체와 C++23 이전 코드는 여전히 미정의 동작이다.
  • explicit이 없는 생성자는 조용한 변환 통로다. Buffer(size_t n)에 explicit이 없으면 Send(100)처럼 숫자를 넘긴 호출이 100바이트 버퍼를 만들어 넘기는 코드로 컴파일된다.
  • 중괄호와 괄호는 컨테이너에서 뜻이 다르다. vector<int>{10}은 원소 하나, vector<int>(10)은 원소 열 개다.
