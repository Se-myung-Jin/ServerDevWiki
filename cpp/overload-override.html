핵심 요약

오버로딩은 한 범위 안에서 같은 이름에 매개변수가 다른 함수를 여럿 두는 것이다. 어느 것을 부를지는 컴파일할 때 인자 타입으로 정해진다. 오버라이딩은 기반 클래스의 가상 함수를 파생 클래스가 같은 시그니처로 다시 정의하는 것이다. 어느 것을 부를지는 실행할 때 객체의 실제 타입으로 정해진다.

둘이 만나는 곳에 함정이 있다. 파생 클래스에 같은 이름의 함수를 하나만 만들어도 기반의 같은 이름 오버로드가 통째로 가려진다. 그리고 시그니처를 조금 틀린 오버라이딩은 오류 없이 새 함수가 된다. C++11의 override가 이것을 막는다.

동작 원리

반환 타입만 다른 두 함수가 오버로드가 될 수 없는 이유는 단순하다. 호출하는 쪽은 반환값을 버릴 수도 있어서, 호출 식만 보고 어느 함수인지 정할 정보가 없다. 멤버 함수 뒤의 const는 시그니처에 들어가므로 const 버전과 비const 버전은 오버로드가 된다. const 객체로 부르면 const 버전이 불린다. 반면 매개변수 맨 바깥의 const(void f(const int))는 시그니처에 들어가지 않는다.

오버로드 해석은 가장 잘 맞는 후보를 고른다

컴파일러는 이름이 같은 후보를 모은 뒤, 인자마다 변환 비용을 매겨 가장 잘 맞는 하나를 고른다. 정확히 맞는 것이 가장 좋고, 그다음이 승격(char → int, float → double), 그다음이 일반 변환(int → double, 파생 → 기반 포인터), 마지막이 사용자 정의 변환(변환 생성자, 변환 연산자)이다. 가장 좋은 것이 하나로 정해지지 않으면 모호하다는 컴파일 오류다. 

void Send(int id);
void Send(const char* name);

Send(0);        // Send(int). 0은 int가 정확히 맞는다
Send(NULL);     // 구현에 따라 Send(int)가 되거나 모호하다는 오류. NULL은 0이나 0L이다
Send(nullptr);  // Send(const char*). nullptr은 포인터로만 변환된다 (C++11)

암묵 변환이 끼면 의도하지 않은 후보가 이길 수 있다. 오버로드마다 인자 타입이 크게 다르지 않다면 이름을 따로 짓는 것이 낫다. 오버로딩은 "같은 일을 다른 입력으로"일 때만 쓴다.

파생에 같은 이름이 생기면 기반의 오버로드가 모두 가려진다

이 규칙은 가상 함수든 아니든, 시그니처가 같든 다르든 똑같다. 기반의 오버로드를 함께 쓰려면 파생 클래스에 using Entity::Hit;을 적어 이름을 끌어온다. "분명히 기반에 있는 함수인데 없다고 하거나 엉뚱한 것이 불린다"는 증상이면 이 가리기를 먼저 의심한다.

override와 final은 의도를 컴파일러에게 알린다

override(C++11)를 붙이면 컴파일러가 기반에 같은 시그니처의 가상 함수가 정말 있는지 확인한다. 없으면 오류다. 안 붙이면 시그니처가 조금만 달라도 새 함수가 조용히 생긴다. 기반 포인터로 부르면 계속 기반 구현이 불린다. 가장 흔한 원인은 const를 빠뜨리거나, 기반 함수의 매개변수 타입이 바뀌었는데 파생 클래스를 고치지 않은 경우다. 

struct Entity {
    virtual void Update(float dt) const;
};
struct Monster : Entity {
    void Update(float dt);            // const가 빠졌다. 오버라이딩이 아니라 새 함수다. 오류 없음
    void Update(float dt) const override;   // 맞다. 틀리면 컴파일 오류가 난다
};

final은 그 뒤로 더 오버라이딩하지 못하게 막는다. 클래스에 붙이면 상속 자체를 막는다. 의도를 드러내는 것 외에, 컴파일러가 그 함수의 호출을 가상 호출이 아닌 직접 호출로 바꿔 인라인할 여지도 준다(가상 함수와 다형성). 한 함수에는 셋 중 하나만 적는다. 새 가상 함수면 virtual, 오버라이딩이면 override, 여기서 끝낼 오버라이딩이면 final이다.

기본 인자는 정적 타입을 따른다

기본 인자는 컴파일 때 호출 식의 정적 타입을 보고 채워진다. 가상 호출로 파생 구현이 불려도 기본값은 기반 선언의 것이 들어간다. 그래서 기반이 Attack(int power = 10), 파생이 Attack(int power = 20) override라면, 같은 객체를 기반 참조로 부르면 파생 구현에 10이, 파생 타입으로 부르면 20이 들어간다. 가상 함수의 기본 인자는 기반에만 두거나 아예 쓰지 않는다.

게임 서버에서는

  • 기반 클래스 시그니처를 바꾸는 날 override가 없으면 조용히 깨진다. 공용 Entity::OnDamaged(int)를 OnDamaged(const DamageInfo&)로 바꾸면, override를 붙인 파생 클래스는 컴파일 오류로 알려 주고 안 붙인 클래스는 옛 시그니처의 새 함수로 남는다. 그 몬스터만 피해 처리가 기본 구현으로 돌아간다. 모든 오버라이딩에 override를 붙이고 Clang의 -Winconsistent-missing-override, GCC의 -Wsuggest-override를 켜 둔다.
  • 처리기 오버로드보다 메시지별 이름이 낫다. Handle(const MovePacket&), Handle(const AttackPacket&)처럼 모든 처리기를 한 이름으로 오버로드하면 템플릿으로 분배하기는 편하지만, 패킷 타입 사이에 변환이 생기는 순간 엉뚱한 처리기가 불린다. 변환 생성자에는 explicit을 붙여 두어야 이 위험이 줄어든다(초기화).
  • C#은 override를 강제하고, C++은 선택이다. C#에서 기반의 virtual 메서드와 같은 시그니처를 override 없이 선언하면 컴파일러가 경고(CS0114)를 내고 기반 메서드를 숨기는 new로 처리한다. C++에서는 virtual이 상속되어 override를 안 붙여도 오버라이딩이 되고, 시그니처가 다를 때만 조용히 새 함수가 된다(인터페이스와 추상 클래스).
  • 이름 가리기는 C#에서 다르게 동작한다. C#은 파생 클래스에 적용할 수 있는 메서드가 있으면 그것을 고르지만, 하나도 맞지 않으면 기반 클래스의 오버로드까지 본다. 위 그림의 예에서 C#은 double을 int로 암묵 변환하지 않으므로 기반의 Hit(double)을 부른다. C++은 파생에서 이름을 찾는 순간 멈추고 1.5를 1로 잘라 넘긴다. 기본 인자가 정적 타입을 따르는 것은 두 언어가 같다.

주의 사항

  • 오버로드와 기본 인자를 섞지 않는다. f(int)와 f(int, int = 0)을 함께 두면 f(1)이 모호해진다. 구현이 하나라면 기본 인자만, 구현이 다르면 오버로드만 쓴다.
  • 시그니처가 다르면 virtual이 붙어 있어도 오버라이딩이 아니다. 매개변수 타입, 개수, 멤버 함수의 const, 참조 한정자(&, &&)까지 같아야 한다.
  • 생성자와 소멸자 안의 가상 호출은 파생 구현을 부르지 않는다. 그 시점의 객체는 아직(또는 이미) 기반 타입이기 때문이다. 자세한 것은 가상 함수와 다형성에서 다룬다.
  • 템플릿과 오버로드가 함께 있으면 정확히 맞는 템플릿이 이길 수 있다. f(long)과 template<class T> f(T)가 있으면 f(1)은 변환이 필요한 f(long) 대신 T = int로 정확히 맞는 템플릿을 고른다(템플릿과 컴파일 시점 계산).
