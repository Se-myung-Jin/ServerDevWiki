먼저 읽을 것: const와 참조 · RAII

핵심 요약

이동은 복사 대신 내부 자원을 넘겨받는 것이다. 원소 백만 개를 가진 std::vector를 복사하면 원소를 백만 번 복사하지만, 이동하면 버퍼를 가리키는 포인터 몇 개만 옮긴다. 곧 사라질 임시 객체나 더는 쓰지 않을 객체에서 복사 비용을 없애려고 C++11에 들어왔다.

std::move는 아무것도 옮기지 않는다. 값을 rvalue 참조로 바꾸는 캐스트일 뿐이고, "이것은 옮겨 가도 된다"는 표시다. 그 표시를 보고 컴파일러가 이동 생성자나 이동 대입을 고르면, 실제로 옮기는 일은 그 함수들이 한다. 이동 생성자가 없으면 아무 경고 없이 복사가 선택된다.

동작 원리

복사는 내용을, 이동은 소유를 옮긴다

이동 생성자는 원본의 포인터를 가져오고 원본의 포인터를 비운다. 원본도 언젠가 소멸자가 불리므로, 비워 두지 않으면 두 객체가 같은 버퍼를 두 번 해제한다. std::exchange(o.ptr_, nullptr)가 "가져오고 비우기"를 한 줄로 쓰는 흔한 방법이다(RAII의 예).

값 범주가 복사와 이동을 가른다

범주무엇인가예고르는 생성자
lvalue이름이 있고 주소를 얻을 수 있는 것a, v[0], *p복사
prvalue이름 없는 순수한 값, 임시 객체f()가 값으로 반환한 것, std::string("x")C++17부터는 대개 생성 자체가 생략된다
xvalue곧 만료될 것으로 표시된 객체std::move(a), static_cast<T&&>(a)이동

prvalue와 xvalue를 합쳐 rvalue라 부르고, T&&(rvalue 참조)는 rvalue에만 묶인다. 함정이 하나 있다. rvalue 참조로 받은 매개변수도 함수 안에서는 이름이 있으므로 lvalue다. void push(std::string&& s) { buf_.push_back(s); }는 복사한다. 넘겨받은 것을 다시 넘길 때도 std::move(s)를 적어야 이동한다. 템플릿에서 받은 그대로의 범주를 넘기는 std::forward는 전달 참조와 완벽 전달에서 다룬다.

이동한 뒤 원본은 "유효하지만 값을 모르는" 상태다

표준 라이브러리 타입은 이동한 뒤에도 소멸자와 대입이 안전하고 불변식이 지켜지지만, 담긴 값은 정해져 있지 않다. 그래서 전제 조건이 없는 연산은 불러도 되고, 전제 조건이 있는 연산은 확인한 뒤에만 부른다.

이동한 객체에되나
소멸시키기, 새 값 대입하기된다. 이동 연산을 만들 때 반드시 이것이 안전하게 해야 한다
empty(), size(), clear()부를 수 있다. 돌아오는 값이 무엇일지 정해지지 않았을 뿐이다
front(), operator*비어 있지 않다는 전제가 있다. 확인하지 않고 부르면 미정의 동작이다

실제 구현은 대부분 비워 두지만 그것에 기대지 않는다. 이동한 변수는 새 값을 넣어 다시 쓰거나 그대로 버린다. 정적 분석 도구(clang-tidy의 use-after-move)가 이 실수를 잡아 준다.

컨테이너는 noexcept 이동만 믿는다

std::vector가 꽉 차면 더 큰 버퍼를 잡고 원소를 옮긴다(배열과 연결 리스트). 옮기던 중 다섯 번째 원소의 이동 생성자가 예외를 던지면, 앞의 네 개는 이미 옛 버퍼에서 빠져나가 되돌릴 수 없다. push_back이 약속한 "실패하면 원래 그대로"를 지킬 수 없다.

그래서 컨테이너는 이동 생성자가 noexcept일 때만 이동하고, 아니면 복사한다(std::move_if_noexcept). 복사는 실패해도 원본이 그대로 남기 때문이다. 이동 생성자를 직접 쓰고 noexcept를 빠뜨리면, 재할당 때마다 원소 전체가 조용히 복사된다. 복사 생성자가 아예 없는 타입이라면 던질 수 있는 이동이라도 쓰고, 그때만 이 보장을 내려놓는다(예외와 예외 안전성).

0, 3, 5의 규칙

규칙뜻
0의 규칙소멸자·복사·이동을 하나도 직접 쓰지 않는다. 자원은 unique_ptr, vector 같은 멤버에 맡기고 컴파일러가 만든 것을 그대로 쓴다. 목표가 이것이다
3의 규칙소멸자, 복사 생성자, 복사 대입 중 하나를 직접 쓰면 나머지 둘도 직접 쓴다. 하나를 쓴다는 것은 자원을 직접 들고 있다는 뜻이라 나머지도 그 자원에 맞춰야 한다
5의 규칙여기에 이동 생성자와 이동 대입을 더한다

5의 규칙이 필요한 이유는 컴파일러의 규칙에 있다. 소멸자나 복사 연산 중 하나라도 직접 선언하면 이동 연산은 자동으로 만들어지지 않는다. 디버그 로그를 찍으려고 빈 소멸자 하나를 적었을 뿐인데, 그 클래스의 모든 std::move가 복사로 바뀐다. 오류도 경고도 없다. 소멸자를 꼭 적어야 하면 이동 연산을 = default로 함께 선언해 둔다.

반환할 때는 std::move를 붙이지 않는다

std::vector<Item> LoadItems() {
    std::vector<Item> items;
    // ... 채운다
    return items;              // 좋다. 생략되거나, 안 되면 이동된다
    // return std::move(items);  // 나쁘다. 생략을 막아 이동 한 번이 생긴다
}

지역 변수를 이름 그대로 반환하면 컴파일러는 그 객체를 호출한 쪽의 자리에 바로 만들어 복사와 이동을 모두 없앨 수 있다(NRVO). 규격은 이것을 허용하지만 강제하지 않는다. 그래도 반환문의 지역 변수는 먼저 rvalue로 취급되므로, 생략이 안 되면 이동이 선택된다. 여기에 std::move를 감싸면 식이 이름이 아니게 되어 생략 조건에서 벗어나고, 이동 한 번이 도로 생긴다. C++17이 반드시 생략하도록 정한 것은 return Item{...};처럼 이름 없는 임시를 반환하는 경우다.

게임 서버에서는

  • 패킷 버퍼는 큐에 이동으로 넘긴다. I/O 스레드가 받은 std::vector<uint8_t>를 로직 스레드의 작업 큐에 넣을 때 queue.push(std::move(buf))로 넘기면 바이트를 복사하지 않는다(게임 서버 스레딩 모델). 넘긴 뒤의 buf는 clear()하고 다시 채우거나 버린다. 비동기 콜백에 넘길 때는 람다의 초기화 캡처 [buf = std::move(buf)]로 옮긴다.
  • const 객체는 이동되지 않는다. const std::string s = ...; v.push_back(std::move(s));는 복사한다. std::move가 const std::string&&을 만들고, 이동 생성자는 const가 아닌 rvalue 참조만 받으므로 복사 생성자가 선택된다. 성능 측정에서 이동이 안 일어나는 원인으로 흔하다.
  • C#에는 이동이 없다. 필요가 없기 때문이다. C#은 클래스가 기본이라 대입이 이미 참조 하나의 복사다. 값 형식(struct)은 작게 만드는 것이 전제이고, 큰 struct를 넘길 때는 in·ref로 복사를 피한다(struct 설계). C++은 값이 기본이라 복사를 피하는 장치가 언어에 필요했고, C#은 참조가 기본이라 그 장치를 GC가 대신한다.

주의 사항

  • std::move를 붙인다고 빨라지지 않는다. 이동 생성자가 없거나, 객체가 const이거나, int처럼 이동과 복사가 같은 타입이면 아무것도 달라지지 않는다. 반환문에서는 오히려 느려진다.
  • 이동한 변수를 다시 읽지 않는다. 값이 남아 있는 것처럼 보이는 구현도 있어서 테스트를 통과하고, 다른 표준 라이브러리나 다른 타입으로 바꾸는 순간 깨진다.
  • 이동 연산에는 noexcept를 붙인다. 빠뜨리면 컨테이너가 재할당 때 복사를 고른다. 이동 중에 정말 예외가 날 수 있는 타입이 아니라면 붙인다.
  • 자기 자신에게 이동 대입해도 깨지지 않게 한다. a = std::move(a)는 드물지만 일반화된 코드에서 생긴다. 이동 대입에서 먼저 자기 자원을 놓고 상대 것을 가져오면 자기 자원을 잃는다.
