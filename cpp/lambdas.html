먼저 읽을 것: 이동 시맨틱 · 스마트 포인터와 소유권

핵심 요약

람다는 컴파일러가 대신 만들어 주는 이름 없는 클래스다. 캡처한 값은 그 클래스의 멤버가 되고, 람다 본문은 operator()가 된다. 그래서 람다 하나는 함수가 아니라 객체이고, 크기와 수명이 있다.

값으로 캡처하면 사본을 들고, 참조로 캡처하면 원본을 가리키는 참조를 든다. 참조 캡처는 원본의 수명을 늘려 주지 않는다. 람다를 그 자리에서 바로 부르면 문제가 없지만, 콜백으로 넘겨 나중에 불리게 하면 원본이 먼저 사라질 수 있다. 비동기 코드에서 람다 버그의 대부분이 여기서 나온다.

동작 원리

람다는 클로저 클래스 하나로 바뀐다

클래스 이름은 컴파일러만 안다. 그래서 람다를 변수에 담을 때는 auto를 쓰고, 함수에 넘길 때는 템플릿 매개변수나 std::function으로 받는다. 같은 모양의 람다를 두 번 써도 타입은 서로 다르다.

캡처가 없는 람다는 멤버가 없으므로 일반 함수 포인터로 바뀔 수 있다. C API에 콜백 함수 포인터를 넘길 때 그대로 쓸 수 있는 이유다. 하나라도 캡처하면 이 변환은 안 된다. 들고 있어야 할 상태를 함수 포인터 하나에 실을 방법이 없기 때문이다.

캡처 방식

쓰는 법무엇을 드나주의할 점
[x], [=]만드는 순간의 사본나중에 원본이 바뀌어도 람다 안 값은 그대로다. 큰 객체면 복사 비용이 든다
[&x], [&]원본을 가리키는 참조원본보다 오래 살면 끊긴 참조다. 그 자리에서 바로 부르는 람다에만 쓴다
[this]this 포인터 하나멤버를 쓰면 실제로는 this->를 거친다. 객체 수명을 늘리지 않는다
[*this] (C++17)객체 전체의 사본원본 객체가 사라져도 된다. 대신 객체를 통째로 복사한다
[p = std::move(p)] (C++14)식의 결과로 새 멤버를 만든다(초기화 캡처)unique_ptr이나 버퍼처럼 복사가 안 되거나 비싼 것을 옮겨 넣는다(이동 시맨틱)
[self = shared_from_this()]객체를 소유하는 shared_ptr콜백이 불릴 때까지 객체가 살아 있다. 자세한 것은 스마트 포인터와 소유권

[=]는 이름과 달리 객체를 복사하지 않는다. 람다 안에서 멤버 hp_를 쓰면 this를 캡처하고 this->hp_로 읽는다. "전부 값으로 잡았으니 안전하다"고 믿기 쉬운 자리라서, C++20은 [=]가 this를 암묵적으로 캡처하는 것을 폐지 예정(deprecated)으로 바꾸고 [=, this]처럼 적게 했다. 지금도 컴파일은 되지만 경고가 나온다.

mutable과 제네릭 람다

int count = 0;
auto next = [count]() mutable { return ++count; };   // 람다 안 사본만 늘어난다
next(); next();                                        // 2를 돌려준다. 바깥 count는 0이다

auto print = [](const auto& v) { Log(v); };            // C++14 제네릭 람다: operator()가 템플릿
auto sum = []<class T>(const std::vector<T>& v) {      // C++20: 템플릿 매개변수를 직접 적는다
    return std::accumulate(v.begin(), v.end(), T{});
};

mutable은 operator()에서 const를 뗀다. 고쳐지는 것은 람다 객체가 든 사본이고 바깥 변수는 그대로다. 람다를 복사해 두 곳에서 부르면 각자 다른 사본을 고친다. 제네릭 람다는 매개변수에 auto를 쓰면 operator()가 템플릿이 되어, 부르는 타입마다 따로 실체가 만들어진다(템플릿과 컴파일 시점 계산).

std::function은 타입을 지우고 대가를 낸다

람다마다 타입이 다르니, 서로 다른 람다를 한 컨테이너에 담거나 멤버 변수로 들려면 공통 타입이 필요하다. std::function<R(Args...)>가 그 일을 한다. 들어온 호출 가능한 객체를 안에 보관하고, 부를 때는 저장해 둔 함수 포인터를 거쳐 간다. 이것을 타입 지우기라고 한다.

비용왜 생기나
힙 할당람다를 안에 담을 공간이 정해져 있다. 그보다 큰 캡처(대개 포인터 두세 개 크기를 넘는 것)는 힙에 따로 할당한다. 이 작은 객체 최적화의 크기는 구현마다 다르다(메모리 할당자)
간접 호출부를 때마다 저장된 포인터를 거친다. 무엇을 부를지 컴파일러가 모르므로 인라인이 막힌다. 가상 함수와 같은 종류의 비용이다(가상 함수와 다형성)
복사 요구std::function은 복사할 수 있어야 해서, 담는 람다도 복사할 수 있어야 한다. unique_ptr을 캡처한 람다는 담을 수 없다
빈 상태아무것도 담지 않은 std::function을 부르면 std::bad_function_call 예외가 난다

C++23의 std::move_only_function은 복사 요구를 없애, 이동만 되는 람다도 담는다. C++26에는 const 정확성을 고친 std::copyable_function과, 소유하지 않고 빌려 부르기만 하는 가벼운 std::function_ref가 더해졌다. 콜백을 보관하지 않고 그 자리에서 부르는 매개변수라면 function_ref가 할당 없이 받는다. 부르기만 하고 보관하지 않는다면 템플릿으로 받는 쪽이 낫다. template<class F> void ForEachNearby(F&& f)처럼 받으면 람다 타입이 그대로 넘어와 호출이 인라인된다.

선택 기준

상황받는 방식이유
함수 안에서 바로 부르고 끝난다(정렬 비교자, 순회 처리)템플릿 매개변수, 캡처는 참조로인라인되고 할당이 없다. 원본이 람다보다 오래 산다
콜백을 보관했다가 나중에 부른다(이벤트, 타이머)std::function 또는 std::move_only_function, 캡처는 값이나 소유 포인터로타입이 하나로 모여야 보관할 수 있다. 참조 캡처는 끊긴다
C API에 함수 포인터로 넘긴다캡처 없는 람다함수 포인터로 바뀐다. 상태는 API가 주는 void* user 인자로 넘긴다
틱마다 수만 번 부르는 짧은 처리템플릿이나 직접 호출std::function의 간접 호출과 할당이 쌓인다

게임 서버에서는

  • 비동기 콜백에는 참조도 this도 그냥 넘기지 않는다. DB 조회를 걸고 [this, &req]로 결과를 받으면, 결과가 오기 전에 세션이 끊겨 객체가 지워지거나 req가 든 스택 프레임이 이미 사라진다. 요청 데이터는 값이나 초기화 캡처로 옮겨 넣고, 객체는 weak_from_this()로 잡았다가 불릴 때 살아 있는지 확인한다.
  • 이벤트 구독은 해제 수단과 함께 돌려준다. OnDamaged.Subscribe([this]{...})로 람다를 등록하고 구독자가 먼저 사라지면, 다음 이벤트에 지워진 this를 부른다. 등록 함수가 구독 토큰을 돌려주고 그 토큰이 소멸할 때 등록을 지우게 하면, 구독자의 수명과 등록의 수명이 함께 묶인다(RAII).
  • 타이머 콜백은 로직 스레드에서 부른다. 버프 만료 같은 콜백을 타이머 자료구조에 std::function으로 넣어 두고 틱마다 꺼내 실행하면, 콜백이 게임 상태를 고쳐도 단일 쓰기 규칙이 지켜진다(타이머 자료구조, 게임 서버 스레딩 모델). 타이머가 수만 개면 std::function 각각의 할당이 쌓이므로 캡처를 작게 유지한다.
  • C#의 클로저는 변수 자체를 공유한다. C#은 캡처한 지역 변수를 컴파일러가 만든 클래스의 필드로 옮기고, 람다와 바깥 코드가 그 필드 하나를 함께 쓴다. 람다를 만든 뒤 바깥에서 값을 바꾸면 람다도 바뀐 값을 본다. C++ 값 캡처는 만든 순간의 사본이라 반대다. 그래서 C#에서는 for (int i...)의 i를 캡처한 람다들이 모두 마지막 값을 보는 버그가 생긴다(foreach는 C# 5부터 반복마다 새 변수다). 캡처마다 그 클래스와 대리자가 힙에 할당되는 것도 서버에서 자주 보는 할당 원인이다. C# 9의 static 람다는 캡처를 금지해 이 할당을 막는다(컴파일러가 바꿔 주는 것, 메모리 누수).

주의 사항

  • [&]를 기본으로 쓰지 않는다. 무엇을 참조로 잡았는지 목록에 드러나지 않아, 람다를 콜백으로 바꾸는 날 끊긴 참조가 조용히 생긴다. 보관되는 람다는 캡처를 하나씩 적는다.
  • [=] 안에서 멤버를 쓰면 this를 잡은 것이다. 값으로 잡았다고 생각해도 객체가 사라지면 끊긴다. 객체 사본이 필요하면 [*this], 멤버 하나만 필요하면 [hp = hp_]로 적는다.
  • std::function을 기본 매개변수 타입으로 쓰지 않는다. 바로 부르고 끝나는 함수까지 std::function으로 받으면, 쓸 일 없는 할당과 간접 호출을 매번 낸다.
  • std::bind 대신 람다를 쓴다. 람다가 읽기 쉽고, 인자가 언제 평가되는지 분명하고, 인라인도 잘 된다. std::bind가 필요한 자리는 C++14 이후로 거의 없다.
  • 정적·전역 변수는 캡처되지 않는다. 캡처 목록에 없어도 람다 안에서 그대로 보이고, 원본을 직접 쓴다. 값으로 잡았다고 착각하기 쉽다.
