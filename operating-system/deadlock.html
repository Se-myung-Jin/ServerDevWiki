먼저 읽을 것: 동기화 객체

핵심 요약

데드락은 서로가 가진 것을 서로 기다려 아무도 나아가지 못하는 상태다. 네 조건이 동시에 성립해야 생기고, 하나만 깨면 생기지 않는다.

실무에서는 대개 순환 대기를 깬다. 자원에 순서를 매겨 그 순서로만 잡는다. 순서를 지킬 수 없는 자리에서는 비선점을 깨서, 못 잡으면 쥐고 있던 것까지 놓고 다시 시도한다.

동작 원리

네 조건이 동시에 성립해야 한다

조건무슨 뜻인가깨려면
상호 배제한 번에 하나만 쓸 수 있다자원을 공유 가능하게 만든다. 대개 불가능하다
점유하고 대기가진 채로 다른 것을 더 기다린다필요한 것을 한 번에 다 잡는다. 무엇이 필요한지 미리 알아야 하고 동시성이 줄어든다
비선점남이 가진 것을 뺏을 수 없다못 잡으면 쥐고 있던 것까지 놓고 다시 시도한다. 중간까지 한 일도 되돌려야 한다
순환 대기기다리는 관계가 고리를 이룬다자원에 순서를 매기고 그 순서로만 잡는다

락을 엇갈려 잡으면 고리가 생긴다

락을 항상 정해진 순서로 잡기로 정해 두면 고리가 생길 수 없다. 규칙이 단순하고 어겼는지 검사하기도 쉽다. 순서의 기준으로는 대상의 ID를 쓴다. 두 유저 사이의 거래라면 ID가 작은 쪽을 먼저 잡게 해 두면, 양쪽 방향의 거래가 동시에 일어나도 고리가 생기지 않는다. 

// 교환: 누가 요청했든 항상 ID가 작은 플레이어의 락부터 잡는다
void Trade(Player a, Player b)
{
    var (first, second) = a.Id < b.Id ? (a, b) : (b, a);
    lock (first.Gate)
    lock (second.Gate)
    {
        // 두 인벤토리를 함께 바꾼다
    }
}

다만 이 순서는 지키자는 약속일 뿐이다. 락에 계층 번호를 붙여, 역순으로 잡으려 하면 디버그 빌드에서 바로 예외를 던지게 해 두는 편이 안전하다.

데드락 · 라이브락 · 기아는 겉모습이 다르다

상태겉모습무슨 일이 벌어지나
데드락관련 스레드가 전부 멈춘다. 블로킹 락이면 CPU 사용률이 0에 가깝고, 스핀락이면 100%로 돈다서로를 기다리며 아무도 안 움직인다
라이브락CPU는 바쁜데 진전이 없다서로 양보하고 재시도하다 계속 같은 자리로 돌아온다
기아전체는 정상으로 동작한다특정 흐름만 차례가 오지 않는다

선택 기준

대응 네 가지 중 무엇을 고르나

전략무엇을 하나어디에 맞나
예방네 조건 중 하나를 구조적으로 못 생기게 한다대부분의 응용. 락 순서 고정이 여기
회피할당해도 안전한지 매번 따져 본다(은행원 알고리즘)자원 요구를 미리 아는 특수한 환경
탐지와 복구생기게 두고 찾아서 푼다데이터베이스. 희생자 트랜잭션을 골라 롤백한다
무시드무니까 그냥 둔다일반 운영체제. 생기면 재시작한다

회피는 교과서 밖에서 거의 쓰지 않는다. 각 흐름이 최대 얼마를 요구할지 미리 알아야 하는데 현실에서는 모른다.

데이터베이스가 탐지 전략을 쓰는 이유는 되돌릴 수 있기 때문이다. 트랜잭션은 롤백하면 없던 일이 되지만, 일반 코드는 중간까지 한 일을 되돌릴 수단이 없다. 그래서 DB를 쓰는 코드는 데드락 오류(SQL Server 1205, MySQL 1213 등)를 정상 흐름으로 받아 다시 시도하도록 구현한다.

게임 서버에서는

  • 여러 객체를 함께 바꾸는 곳이 위험하다. 거래, 파티·길드 가입, 우편 수령처럼 두 객체 이상을 함께 바꾸는 기능에서 생긴다. 위 예제처럼 ID 순서를 정하거나, 길드 → 플레이어 → 인벤토리처럼 계층 순서를 문서로 정해 둔다.
  • sync-over-async도 데드락이다. 한 스레드에서만 이어 실행하는 SynchronizationContext를 쓰는 서버(로직 스레드 하나에 continuation을 몰아주는 구조)에서 task.Result나 .Wait()를 부르면, 그 스레드가 결과를 기다리느라 멈추고 결과를 만들 continuation은 같은 스레드를 기다려 영원히 멈춘다. 비동기 메서드는 끝까지 await한다.
  • 덤프로 찾는다. 서버가 멈추면 dotnet-dump collect로 덤프를 뜨고 dotnet-dump analyze의 syncblk(누가 어떤 락을 쥐었나)와 clrstack -all(누가 무엇을 기다리나)로 고리를 확인한다.

주의 사항

  • 조건 하나가 성립한다고 데드락이 되지는 않는다. 넷이 동시에 성립해야 생기고, 그래서 하나만 깨면 나머지가 다 성립해도 생기지 않는다.
  • 타임아웃만으로는 데드락을 막지 못한다. Monitor.TryEnter(…, timeout)으로 일정 시간 뒤 포기하기만 하면 고리는 그대로 생기고, 걸린 뒤에 빠져나올 뿐이다. 막으려면 포기할 때 쥐고 있던 것까지 놓고 처음부터 다시 잡아야 한다. 이때 둘이 같은 실패를 되풀이하는 라이브락이 생길 수 있어, 다시 잡기 전에 무작위로 조금 기다린다.
  • 락 안에서 남의 코드를 부르지 않는다. 락을 쥔 채 이벤트 핸들러, 콜백, 가상 메서드를 부르면 그 안에서 어떤 락을 잡을지 알 수 없어 순서 규칙이 깨진다.
