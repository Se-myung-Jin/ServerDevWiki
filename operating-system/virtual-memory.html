먼저 읽을 것: 프로세스 메모리 구성

핵심 요약

가상 메모리는 프로세스마다 독립된 주소 공간을 주고, 그 주소를 실행 시점에 물리 주소로 번역하는 구조다. 번역은 CPU 안의 MMU라는 하드웨어가 한다.

주소를 한 겹 감싸는 것만으로 여러 가지가 함께 따라온다. 프로세스끼리 격리되고, 물리 메모리보다 큰 주소 공간을 쓸 수 있고, 흩어진 물리 메모리를 연속된 것처럼 보이게 해 물리 메모리의 외부 단편화를 감춘다. 여러 프로세스가 같은 물리 메모리를 함께 보게 만드는 공유도 같은 구조로 한다.

동작 원리

같은 주소가 프로세스마다 다른 곳을 가리킨다

가상 주소 공간을 고정 크기(x86-64는 보통 4KB)로 나눈 조각이 페이지이고, 물리 메모리를 같은 크기로 나눈 칸이 페이지 프레임이다. 페이지 테이블은 어느 페이지가 어느 프레임에 들어 있는지, 그리고 읽기·쓰기·실행 권한을 적어 둔 표이고, 프로세스마다 따로 있다.

프로세스를 바꿀 때는 페이지 테이블을 가리키는 레지스터(x86의 CR3)만 바꾸면 번역 대상이 통째로 바뀐다. 그래서 컨텍스트 스위칭은 메모리 내용을 옮기지 않는다.

공유 라이브러리를 메모리에 하나만 올려 두고 여러 프로세스가 쓰는 것, fork한 자식이 부모 메모리를 복사하지 않고 함께 보다가 한쪽이 쓰는 순간에만 그 페이지를 복사하는 것(copy-on-write)이 모두 이 방식이다.

물리 메모리보다 큰 주소 공간을 어떻게 쓰나

모든 페이지가 물리 메모리에 올라와 있을 필요가 없다. 처음 접근할 때 비로소 프레임을 주고(demand paging), 당장 쓰지 않는 페이지는 디스크(스왑, Windows의 페이지 파일)로 내려보냈다가 다시 접근하면 올린다. 이 과정은 페이지 폴트로 일어난다.

그래서 주소 공간의 크기가 물리 메모리 크기에 묶이지 않는다. 대신 디스크로 내려간 페이지에 접근하는 순간은 메모리 접근보다 수천 배 이상 느리다.

고정 크기로 자르면 연속된 빈 공간을 찾을 필요가 없다

프레임 크기가 모두 같으니 비어 있는 프레임이면 어디에 넣어도 된다. 흩어진 프레임을 모아 주고, 페이지 테이블이 연속처럼 보이게 만든다. 대신 페이지 끝에 남는 자리가 생긴다. 이것이 내부 단편화이고, 외부 단편화와 맞바꾼 셈이다(단편화).

선택 기준

가상 크기와 실제 사용량을 구분해서 본다

지표뜻판단에 쓰나
가상 크기 (VSZ, Virtual Size)예약하거나 매핑한 주소 공간 전체메모리 부족 판단에는 쓰지 않는다. 64비트에서는 매우 커도 정상이다
상주 크기 (RSS, Working Set)지금 물리 메모리에 올라와 있는 페이지실제 메모리 사용량 판단에 쓴다
커밋 크기 (Private Bytes, Commit)물리 메모리나 페이지 파일로 보장해 둔 양Windows에서 메모리 누수를 볼 때 쓴다

게임 서버에서는

  • .NET 서버의 가상 크기는 원래 크다. GC는 힙으로 쓸 주소 범위를 미리 크게 예약해 두고 필요할 때 실제 메모리를 붙인다. 그래서 작업 관리자나 top의 가상 크기는 수십~수백 GB로 보일 수 있다. 메모리 알람은 상주 크기(Working Set, RSS)와 GC 힙 크기로 건다.
  • 스왑이 시작되면 틱이 무너진다. 게임 서버의 메모리가 물리 메모리를 넘어 스왑으로 밀리면, 평소 나노초 단위이던 접근이 디스크 대기가 되어 틱 지연이 수십~수백 ms로 튄다. 서버 머신은 메모리에 여유를 두고, 컨테이너라면 메모리 제한을 명시해 차라리 일찍 OOM으로 재시작되게 한다.
  • 32비트 프로세스는 가상 주소 공간이 먼저 바닥난다. 물리 메모리가 남아 있어도 2~4GB 주소 공간이 조각나면 큰 배열을 할당하지 못하고 OutOfMemoryException이 난다(32비트와 64비트).

주의 사항

  • 가상 메모리는 "메모리가 부족할 때 디스크를 쓰는 기능"만이 아니다. 그것은 여러 쓰임 중 하나다. 격리, 단편화 은닉, 페이지 공유, 권한 보호가 같은 구조에서 함께 이루어지고, 메모리가 넉넉한 요즘 기계도 가상 메모리를 쓴다.
  • 외부 단편화가 완전히 사라지는 것은 아니다. 물리 메모리의 단편화는 감춰지지만, 가상 주소 공간 자체도 조각날 수 있다. 64비트에서는 공간이 워낙 커서 거의 문제가 안 되고, 32비트에서는 실제로 문제가 된다.
  • 번역은 공짜가 아니다. 메모리 접근마다 페이지 테이블을 보면 느려지므로 TLB라는 캐시가 따로 있다(페이징과 TLB).
