먼저 읽을 것: 계층 모델

핵심 요약

헤더 필드를 외우는 것이 목적이 아니다. 무엇이 들어 있느냐가 그 프로토콜이 무엇을 보장하는지를 말해 준다. TCP 헤더에는 순서 번호와 확인 응답 번호가 있고 UDP 헤더에는 없다. 그래서 TCP는 순서와 도착을 보장하고 UDP는 보장하지 않는다.

크기도 거기서 나온다. TCP 헤더는 최소 20바이트, UDP 헤더는 8바이트, IPv4 헤더는 최소 20바이트, IPv6 헤더는 고정 40바이트다. 한 번에 실을 수 있는 크기(MTU)를 넘으면 조각으로 나뉘는데, 조각 하나만 잃어도 전체를 잃으므로 처음부터 나뉘지 않게 보낸다.

TCP 옵션이 붙을 수 있어 헤더 길이가 20~60바이트로 바뀐다. 그래서 헤더가 어디서 끝나고 데이터가 어디서 시작하는지를 알려 주는 필드(data offset)가 헤더 안에 따로 있다. 헤더의 여러 바이트 값은 모두 빅 엔디안(네트워크 바이트 오더)으로 적힌다(엔디안과 바이트 오더).

TTL은 경로가 고리를 이룰 때 패킷이 영원히 도는 것을 막는 장치다. traceroute는 TTL을 1, 2, 3…으로 늘려 보내며 각 라우터가 돌려주는 "시간 초과" 응답으로 경로를 그린다.

MTU를 넘으면 조각으로 나뉜다

한 프레임에 실을 수 있는 최대 크기가 MTU다. 이더넷은 보통 1500바이트다. IP 패킷이 경로 중 어느 구간의 MTU보다 크면 조각으로 나뉘고, 받는 쪽에서 모두 모여야 다시 합쳐진다. 조각 하나만 잃어도 패킷 전체를 버리므로, 조각이 많을수록 잃을 확률이 높아진다.

장치어떻게
MSSTCP는 연결을 맺을 때 한 세그먼트에 실을 데이터 최대 크기를 서로 알린다. 이더넷·IPv4면 1500 − 20(IP) − 20(TCP) = 1460바이트. 처음부터 조각으로 나뉘지 않게 잘라 보낸다
경로 MTU 탐색(PMTUD)"나누지 말 것(DF)"을 켜고 보내, 중간에서 너무 크다는 ICMP 응답이 오면 크기를 줄인다
UDP응용이 보낸 크기가 그대로 내려간다. 크기 제한은 응용이 직접 해야 한다

경로 중간의 방화벽이 ICMP를 막으면 "너무 크다"는 응답이 돌아오지 않는다. 그러면 연결은 맺어지는데 큰 데이터만 가지 않는 증상(PMTU 블랙홀)이 생긴다. 작은 로그인 패킷은 가는데 큰 캐릭터 정보에서 멈추는 식이다. VPN·터널은 자기 헤더를 더 붙여 실제 MTU를 줄이므로 이 증상이 특히 잦다.

선택 기준

작은 패킷에서는 헤더가 대부분이다

전송 방식헤더(IP + 전송)데이터 20바이트일 때 헤더 비율
TCP / IPv440바이트약 67%
UDP / IPv428바이트약 58%
UDP / IPv648바이트약 71%

여기에 이더넷 헤더와 프레임 사이 간격까지 더하면 선 위에서는 프레임마다 30~40바이트가 더 든다. 이동 패킷처럼 작은 메시지를 하나씩 보내면 대역폭 대부분이 헤더다. 그래서 작은 메시지는 한 패킷에 여러 개를 묶어 보낸다. 묶는 시간과 지연의 균형은 작은 패킷과 지연에서 다룬다.

게임 서버에서는

  • UDP 게임 패킷은 1,200바이트 안팎으로 묶는다. IPv6의 최소 MTU가 1280바이트라, 그 아래로 잡으면 거의 모든 경로에서 조각으로 나뉘지 않는다. QUIC도 같은 이유로 1,200바이트를 기준으로 쓴다. 더 큰 데이터는 응용이 쪼개고 번호를 붙여 보낸다.
  • TCP는 바이트 흐름이지 패킷이 아니다. 헤더에 메시지 경계를 적는 필드가 없다. 보낸 Send 한 번이 받는 쪽 Receive 한 번과 맞는다는 보장이 없으니, 길이 필드를 앞에 붙여 응용이 경계를 정한다(메시지 경계와 프레이밍).
  • 패킷 캡처로 헤더를 직접 본다. 연결이 이상하면 Wireshark나 tcpdump로 SYN·RST·재전송·윈도 값을 확인한다. "서버가 RST를 보냈다"인지 "아예 응답이 없다"인지가 원인을 크게 가른다.

주의 사항

  • 필드를 나열하는 것과 무엇을 해 주는지 말하는 것은 다르다. 순서 번호가 있으니 순서를 맞추고, 확인 응답이 있으니 다시 보낸다. 헤더에서 읽어 내야 하는 것은 이 대응이다.
  • 체크섬은 위변조를 막지 못한다. 우연한 전송 오류를 잡는 16비트 합계라, 내용을 고치고 체크섬을 다시 계산하면 그만이다. 위변조는 암호로 막는다(서명과 TLS).
  • IPv6 헤더가 더 크다고 느린 것은 아니다. 고정 길이에 체크섬이 없어 라우터가 처리하기는 오히려 단순하다. 작은 패킷에서 비율만 커질 뿐이다.
